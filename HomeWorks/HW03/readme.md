Разберем задание № 6 более подробно.

Представим исходный MAC-адрес 255.255.255.0 в двоичной системе, получим 11111111.11111111.11111111.00000000. Значит сетевая часть адреса будет 192.135.250.0.

Используя новую маску подсети 255.255.255.248, возьмем из 4 октета 5 бит для подсети и получим 2^5=32 подсети. 

Оставшиеся 3 бита, будут идентификаторами узлов сети 2^3-2=6.

Шаг сети 256-248 = 8

Рассмотрим получившиеся варианты:

Первая подсеть будет иметь вид: 192.135.250.00000000/29 =  192.135.250.0

192.135.250.00000001 = 192.135.250.1 1Fs

192.135.250.00000010 = 192.135.250.2 2Se

..

192.135.250.00000110 = 192.135.250.6 Last

192.135.250.00000111 = 192.135.250.7 Br

IP-адрес из задания 192.135.250.180 попадает в подсеть:

192.135.250.10110000 = 192.135.250.176

192.135.250.10110001 = 192.135.250.177 1Fs

..

192.135.250.10110110 = 192.135.250.182 Last

192.135.250.10110111 = 192.135.250.182 Br

## Вопрос для повторения
Почему маска подсети так важна при анализе IPv4-адреса?

Потому что только благодаря маске подсети мы можем выделить сетевую и узловую часть IPv4-адреса.
